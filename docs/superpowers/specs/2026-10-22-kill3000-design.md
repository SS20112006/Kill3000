## 1. Executive Summary & Vision

**Kill3000** is an open-source, ultra-lightweight macOS menu bar utility built specifically for developers. It eliminates the frequent developer pain point: `Error: listen EADDRINUSE: address already in use :::3000` or orphaned background servers holding ports hostage.

Living seamlessly in the macOS menu bar, Kill3000 detects active TCP listening ports on `localhost`, intelligently highlights developer-spawned processes (Node, Vite, Python, Go, Docker, etc.) while filtering out background system daemons, and enables one-click process termination (`SIGTERM` with `SIGKILL` escalation) or opening the URL in the default browser.

As a portfolio showcase, Kill3000 exemplifies:
1. **Modern Swift & SwiftUI**: Native Swift 6 concurrency (`actor`), `@Observable` state management, and `MenuBarExtra`.
2. **Apple Human Interface Guidelines (HIG)**: San Francisco typography optical sizing, semantic system materials (`.ultraThinMaterial`), WCAG 2.1 AA accessibility, and sensory haptic feedback.
3. **Decoupled Architecture**: Clean separation between domain engine (`Kill3000Engine`) and UI (`Kill3000App`).
4. **Zero Bloat & Ponytail Simplicity**: Under 30MB of RAM, 0% CPU consumption when closed, and zero external binary dependencies.

## 2. Requirements & Scenarios

### 2.1 Core User Stories
* **Scenario A (Inspect Active Dev Ports)**: The developer clicks the Kill3000 menu bar icon and immediately sees a clean list of active local ports (e.g., `:3000`, `:5173`, `:8080`), their associated executable names (`node`, `vite`, `python3`), process IDs (PID), and username.
* **Scenario B (Kill Stuck Port)**: The developer clicks the "Kill" button on a port holding up their build. The app sends `SIGTERM` to allow graceful shutdown, checks process liveness, escalates to `SIGKILL` if still alive after 1.5 seconds, triggers sensory haptic feedback, and immediately removes the item from the list.
* **Scenario C (Filter System vs Dev)**: By default, internal macOS system daemons (e.g. `mDNSResponder`, `rapportd`, `cupsd`) are filtered out to keep the interface focused on development tasks. A segmented toggle lets the user view "All Ports (including System)" when diagnosing complex port conflicts.
* **Scenario D (Open in Browser)**: The developer clicks the browser action button next to `:3000` to quickly open `http://localhost:3000` in their default browser.
* **Scenario E (Search & Filter)**: The developer types "5173" or "vite" into the top search bar to filter the visible list in real time.

### 2.2 Non-Functional Requirements & Security
* **Battery & CPU Efficiency**: The background polling mechanism runs strictly while the popover window is open (`.onAppear` to `.onDisappear`). Polling terminates immediately when closed, reducing background CPU usage to 0%.
* **Security & Process Isolation**:
  * PIDs `<= 1` (`0` and `1` / `launchd`) are explicitly forbidden from being targeted.
  * No `sudo` execution or privilege escalation hacks. If a user attempts to kill a process owned by `root` or another user, the POSIX `EPERM` error is caught and converted to a non-crashing, user-friendly notification.
  * ReDoS Protection: All regex patterns matching CLI output use strictly bounded expressions.
* **Zero Public Leakage**: No internal developer workstation paths, personal credentials, or secrets are tracked or serialized.

## 4. Component Details & Data Flow

### 4.1 Domain Models
* **`ProcessCategory`**:
  ```swift
  public enum ProcessCategory: String, Sendable, CaseIterable {
      case development = "Dev Server"
      case systemDaemon = "macOS System"
  }
  ```
* **`ActivePort`**:
  ```swift
  public struct ActivePort: Identifiable, Sendable, Equatable {
      public var id: String { "\(port)-\(pid)" }
      public let port: Int
      public let pid: pid_t
      public let processName: String
      public let commandPath: String?
      public let user: String
      public let protocols: Set<String> // ["IPv4", "IPv6"]
      public let category: ProcessCategory
  }
  ```

### 4.2 System Services
1. **`PortScanner` (Actor)**:
   * Spawns `/usr/sbin/lsof -iTCP -sTCP:LISTEN -n -P` asynchronously off the main thread.
   * Feeds raw output into `PortParser`.
2. **`PortParser`**:
   * Uses regular expression matching for TCP listen rows:
     `^(\S+)\s+(\d+)\s+(\S+)\s+\S+\s+(IPv4|IPv6)\s+\S+\s+\S+\s+TCP\s+(?:\*|127\.0\.0\.1|\[::1\]|localhost):(\d+)\s+\(LISTEN\)`
   * Groups rows with identical `(port, pid)` to merge dual IPv4/IPv6 bindings into a single item.
3. **`ProcessInspector`**:
   * Inspects process names:
     * **Development**: `node`, `vite`, `next`, `bun`, `deno`, `python`, `python3`, `go`, `cargo`, `ruby`, `docker-proxy`, `postgres`, `redis-server`, `java`.
     * **System Daemons**: `mDNSResponder`, `rapportd`, `cupsd`, `ControlCenter`, `launchd`, `identityservicesd`, `sharingd`.
4. **`ProcessTerminator`**:
   * Safety guard: asserts `pid > 1`.
   * Sends `kill(pid, SIGTERM)`.
   * Waits up to 1.5 seconds checking `kill(pid, 0) == 0`.
   * If still alive, issues `kill(pid, SIGKILL)`.
   * Maps POSIX errno (`EPERM`, `ESRCH`) to typed domain errors (`TerminatorError.permissionDenied`, etc.).

## 5. UI/UX & Apple Human Interface Guidelines (HIG)

### 5.1 Design Tokens & Ergonomics
* **Typography**:
  * Large headers (`>= 20pt`): **SF Pro Display**, bold tracking.
  * Standard text (`<= 19pt`): **SF Pro Text**, standard optical spacing.
  * Port numbers: `.font(.system(.body, design: .monospaced))` for strict vertical visual alignment.
* **Materials & Translucency**:
  * Popover background: `.background(.ultraThinMaterial)` for native macOS translucency.
  * No flat or arbitrary hex colors for window chrome.
* **Ergonomics & Touch Targets**:
  * Minimum physical footprint of **44x44 points** for all interactive click targets (`.frame(minWidth: 44, minHeight: 44)`).
* **Sensory Feedback**:
  * Uses `.sensoryFeedback(.impact, trigger: ...)` upon successful process termination.
  * Uses `.sensoryFeedback(.selection, trigger: ...)` when switching filter pills.
  * Uses `.sensoryFeedback(.error, trigger: ...)` upon operation failures.
* **Contrast & Accessibility**:
  * All foreground/background pairings exceed **4.5:1** contrast ratio (WCAG 2.1 AA).

## 6. Testing Strategy

1. **`PortParserTests`**:
   * Verify IPv4 listen lines (`127.0.0.1:3000`).
   * Verify IPv6 listen lines (`[::1]:3000`).
   * Verify wildcard listen lines (`*:5173`).
   * Verify deduplication: single process listening on both IPv4 and IPv6 results in one `ActivePort` with protocols `["IPv4", "IPv6"]`.
2. **`ProcessClassifierTests`**:
   * Assert all common dev stacks (`node`, `vite`, `python3`, `docker-proxy`) evaluate to `.development`.
   * Assert macOS system daemons evaluate to `.systemDaemon`.
3. **`ProcessTerminatorTests`**:
   * Assert safety guard prevents killing PID 0 or PID 1.
   * Verify graceful error handling when attempting to kill non-existent PID (`ESRCH`).
4. **End-to-End Smoke Test**:
   * Automated verification: spin up background server on ephemeral port (e.g. 8999), verify detection by `PortScanner`, verify termination and port release.
